# Generated-case contract

`generated.rs` is reusable graph-only test support imported by engine and CLI integration tests. It depends on graph-core and test-only proptest, never on engine or parser. A separate testkit crate is unnecessary for this small shared module; the five production crates retain their dependency boundaries.

Proptest 1.6.0 is pinned with only its std feature. Each of eight property campaigns defaults to 64 accepted recipes; `S3_CASES` permits 1–4096 and the extended workflow uses 512. `S3_SEED` defaults to decimal 5452614. Its eight little-endian bytes are repeated four times for proptest's named ChaCha generator. This generator controls test inputs, not the engine scheduler. Shrinking is capped at 4096 iterations. No property uses filters or rejected inputs; the run prints requested/evaluated recipes and seed. Replayed regression seeds add evaluations beyond the requested count.

Recipes rebuild references instead of deleting arbitrary indexed atoms during shrinking. Object recipes have 2–5 constructors and 0–6 links, with sharing, cycles, self-links, parallel records and short ASCII or selected Unicode/control labels. LN maps endpoints to distinct constructors. Self-lowerers have ranks 0–3 and sequences of 1–3 heads. Inactive lowerers may have deliberately partial but permitted sides. Fresh installers have depth 0–3 and active/inactive children. Complete-exit recipes consume a target's entire representation and revision. Promotions change two heads in one event and have fixed successful, GC-invalid and revision-invalid variants. Other targeted invalid families retain dangling, shared quotation, incomplete package, missing metadata, incomplete binding and hidden-grounding witnesses while unrelated object noise shrinks.

Positive promotion recipes guarantee one successful explicitly bound candidate in every evaluation. Both fault variants must reject atomically, including the allocator probe. LN/reflective sequence lengths vary and may be zero; those cases are not counted as successful transitions merely because a property passed. The package campaign explicitly conditions execution on an active installer of positive depth. There is no measured rejection bottleneck: zero generated cases are filtered, and expected semantic rejections are assertions, not discarded inputs.

The shrink traversal regression checks well-formed references, valid inactive/package structure and the retained GC violation. Failures are persisted per property under each consuming crate's `proptest-regressions/`; commit the seed and shrunken recipe with a focused regression. The first retained failure reduced to an inactive depth-three package whose renamed comparison exhausted five million work units. Bounded incidence refinement fixes that case; an explicit regression now requires completion within one million. A same-colour pair of one six-cycle versus two three-cycles checks that refinement alone never decides equality.

Default runs evaluate 512 new recipes plus the retained seed. Three extended runs at seeds 5452614, 1 and 987654321 evaluate 12,288 new recipes plus three regression replays. These are recipe counts, not coverage percentages, transaction counts or proofs. Blind spots include arbitrary recursive quotation, all malformed configurations, large symmetric carriers, exhaustive reflective overlaps, acceptance completeness, native/WebAssembly execution parity and performance. Existing targeted conformance tests remain necessary. All scripts use the pinned Rust 1.85.0 toolchain; the WebAssembly check builds production dependencies only.
